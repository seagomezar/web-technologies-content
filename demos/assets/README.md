# Demo Assets (`demos/assets`)

## Overview

Shared browser helpers, zero-dependency finite state machine (`Lab.createMachine`) runtime, Chrome Built-in AI session adapters, WebMCP tool registration utilities, and interactive demo controllers for the 21 standalone Web AI Lab demo pages in `../` (`demos/`). Each JavaScript file executes as an IIFE loaded via `<script defer>` after `../locale-data.js`, `../i18n.js`, and `../content-data.js`, reading `document.body.dataset.demo` to hydrate the matching demo module onto `#app` with explicit `[data-machine][data-state]` and `aria-busy` attributes.

## Interface

- `[lab.js:window.Lab]` — Shared DOM, localization, state-machine, similarity, download, and Chrome Built-in AI adapter namespace attached to `window`: `{ $, $$, esc, id, topic, demo, app, status, panel, output, result, run, createMachine, bindMachine, machines, inspectMachines, available, create, withSession, prompt, words, overlap, cosine, download }`.
- `[lab.js:createMachine]` / `[lab.js:bindMachine]` / `[lab.js:machines]` / `[lab.js:inspectMachines]` — Deterministic finite state machine factory (`{ id, initial, context, states, onTransition, host, busyStates }`) supporting declarative `{ states: { [state]: { busy, entry, exit, on: { [event]: target | { target, guard, assign, effect } | Array<Rule> } } } }` transition tables, exposing `{ id, isBusy, getState, getContext, can, getSnapshot, subscribe, send }` (`getSnapshot()` returns `{ id, state, context, allowedEvents }`), syncing `[data-machine="<id>"][data-state="<state>"]` and `aria-busy="true" | "false"` onto bound host elements, registering every instance in `window.Lab.machines` (`Map`), and returning JSON-serializable snapshots via `window.Lab.inspectMachines()` for browser agents and DevTools (AX).
- `[lab.js:$]` / `[lab.js:$$]` / `[lab.js:esc]` — Scoped `querySelector` / `querySelectorAll` array helpers and HTML entity escaper (`&`, `<`, `>`, `"`, `'`).
- `[lab.js:id]` / `[lab.js:topic]` / `[lab.js:demo]` / `[lab.js:app]` — Active demo slug from `document.body.dataset.demo`, matched `CONTENT_TOPICS` topic/demo metadata objects, and `#app` mount element.
- `[lab.js:status]` / `[lab.js:panel]` / `[lab.js:output]` / `[lab.js:result]` / `[lab.js:run]` — Localized `#status` updater (via `I18N.text`), panel/output HTML builders, string/JSON `#result` writer, and FSM-backed async click wrapper (`'run:<selector>'`: `idle -> running -> succeeded | error`, accepting optional `{ disabledWhen }` predicate) with re-entrancy protection, button disablement, and error capture.
- `[lab.js:sessionPool]` / `[lab.js:available]` / `[lab.js:create]` / `[lab.js:withSession]` / `[lab.js:prompt]` — Explicit session-pool state machine (`'ai-session-pool'`: `idle -> creating -> active | error`) and Chrome Built-in AI session lifecycle adapters over `globalThis[name]` (`LanguageModel`, `Summarizer`, `Proofreader`, `Translator`, `LanguageDetector`, `SemanticEmbedder`) injecting English-only `nativeOptions` defaults for `LanguageModel` (`expectedInputs`/`expectedOutputs` `['en']`), `Summarizer` (`type: 'key-points', format: 'plain-text', length: 'short', expectedInputLanguages: ['en'], outputLanguage: 'en'`), and `Proofreader` (`expectedInputLanguages: ['en']`), returning `'not exposed'` from `available()` when `globalThis[name]?.availability` is absent, wiring `downloadprogress` monitors, forwarding `AbortSignal`, and releasing sessions via `destroy()`.
- `[lab.js:words]` / `[lab.js:overlap]` / `[lab.js:cosine]` / `[lab.js:download]` — NFD-normalized alphanumeric word-set tokenizer, lexical Ochiai overlap scorer, equal-length vector cosine similarity function, and JSON `Blob` file downloader.
- `[lab.js:is-embedded]` — URL query flag (`?embed=1`) and iframe check (`window.self !== window.top`) that adds `is-embedded` to `document.body.classList`.
- `[lab.css]` — Shared visual theme plus zero-CLS inset `box-shadow` affordances for `[data-machine][aria-busy="true"]` and terminal/review `[data-state]` hosts, paired with `@media (forced-colors: active)` `outline` fallbacks.
- `[decisions.js:routerMachine]` / `[decisions.js:airlockMachine]` / `[decisions.js:abstentionMachine]` — Explicit state machines for `issue-router` (`idle -> routing -> routed_billing | routed_technical | routed_review -> stale | error`), `comment-airlock` (`editing -> evaluating_model -> allowed | escalated_review | error`), and `abstention-lab` (`idle -> evaluating -> evaluated | error`).
- `[languages.js:relayMachine]` / `[languages.js:radarMachine]` / `[languages.js:proofreadMachine]` — Explicit state machines for `bilingual-relay` (`editing -> checking_availability | translating -> translated | error`), `language-radar` (`idle -> detecting -> detected -> stale | error`), and `proofread-review` (`editing -> proofreading -> review_ready -> accepted | rejected`).
- `[lifecycle.js:conciergeMachine]` / `[lifecycle.js:streamMachine]` / `[lifecycle.js:passportMachine]` — Explicit state machines for `model-concierge` (`idle -> checking -> ready -> preparing_session -> session_verified | error`), `stream-garden` (`idle -> rehearsing | streaming -> completed | aborted | error`), and `iframe-passport` (`idle -> probing -> allowed | denied | error`, handling `{ kind: 'ai-policy-probe' }` messages from `<iframe id="probe">`).
- `[performance.js:latencyMachine]` / `[performance.js:preferenceMachine]` / `[performance.js:backpackMachine]` — Explicit state machines for `latency-lens` (`empty -> running -> recorded -> exported`), `preference-kitchen` (`invalid_config <-> valid -> summarizing -> summarized`), and `context-backpack` (`ready -> measuring -> measured -> stale | error`).
- `[recipes.js:remixMachine]` / `[recipes.js:releaseMachine]` / `[recipes.js:arenaMachine]` — Explicit state machines for `voice-remix` (`template_ready -> generating -> generated | error`), `release-kitchen` (`valid <-> invalid_facts`, `valid -> generating -> citations_verified | citation_drift`), and `recipe-arena` (`idle -> running_summarizer -> running_prompt -> compared -> reviewed | stale`).
- `[retrieval.js:compassMachine]` / `[retrieval.js:constellationMachine]` / `[retrieval.js:evidenceMachine]` — Explicit state machines for `meaning-compass` (`idle -> ranking -> ranked -> stale | error`), `duplicate-constellation` (`stale -> computing -> ready`), and `evidence-window` (`unranked -> ranking -> insufficient_evidence | ready_to_draft -> drafting -> verified | citation_warning`).
- `[webmcp.js:webmcpEnv]` / `[webmcp.js:routeMachine]` / `[webmcp.js:modalMachine]` / `[webmcp.js:copyMachine]` / `[webmcp.js:consentMachine]` / `[webmcp.js:observatoryMachine]` — Explicit WebMCP environment machine (`'webmcp-env'`: `detecting -> native_active | simulation_only | registration_error`) plus demo machines for `reading-route` (`empty <-> populated`, `'onboarding-modal'` `closed <-> open`, `'clipboard-copy'` `idle -> copying -> copied | failed -> idle`), `consent-cart` (`idle -> awaiting_review -> confirmed | rejected | cancelled`), and `tool-observatory` (`idle -> executing -> succeeded | structured_error | invalid_json`) with default tool annotations `{ readOnlyHint: false, untrustedContentHint: false, consequentialHint: false }` (`[webmcp.js:card]`).
- `[webmcp.js:getModelContext]` / `[webmcp.js:hasWebMCP]` — URL query flags where `webmcp=0` or `forceModal=1` causes `getModelContext()` to return `null` across all 3 WebMCP demos (and forces `hasWebMCP()` false to open `#webmcp-modal` on `reading-route`), while `webmcp=1` forces `hasWebMCP()` true for `reading-route` UI state without supplying a `modelContext` object to `getModelContext()`.
- `[webmcp.js:window.addToRoute]` — Global helper `(args, source = 'tool') => add(args, source)` exposed on `reading-route`; accepts `{ articleId: string }` (matching canonical IDs `models`, `browserdj`, `patterns`, `ownership` as well as case-insensitive EN/ES titles and substring aliases) and returns `{ status: 'added', article, route }`, `{ status: 'already-added', article }`, or `{ error, code: 'INVALID_ARGUMENT' | 'UNKNOWN_ARTICLE', retryable: true }`.
- `[webmcp.js:add_to_route]` — WebMCP tool registered via `(document.modelContext || navigator.modelContext).registerTool` on `reading-route` with `inputSchema` `{ type: 'object', properties: { articleId: { type: 'string' } } }` (omitting `required`).
- `[webmcp.js:request_demo_ticket_confirmation]` — Consequential WebMCP tool (`annotations.consequentialHint: true`, `required: ['quantity']`) registered on `consent-cart` validating integer `quantity` in `1..4` (returning `code: 'INVALID_QUANTITY'`, `retryable: true` otherwise) and resolving to `{ status: 'confirmed', quantity }`, `{ status: 'rejected' }`, or `{ status: 'cancelled' }`.
- `[webmcp.js:find_demo]` / `[webmcp.js:inspect_state]` — Read-only WebMCP tools registered unconditionally on `modelContext` at load in `tool-observatory` (`find_demo` requires `{ query: string }` with `readOnlyHint: true`, returning `INVALID_QUERY` or `{ matches: Array<{ id, title }> }`; `inspect_state` returns `{ time, topicCount, source: 'local-debug-state', machines: Lab.inspectMachines() }` with `readOnlyHint: true, debugging: true`).

## Invariants

- `[lab.js:demo]` — `lab.js` returns early before defining `window.Lab` if `document.body.dataset.demo` does not match any demo entry in `CONTENT_TOPICS`; all sibling feature scripts destructure `Lab` at load time and require a valid registered `data-demo` attribute.
- `[lab.js:createMachine]` — Throws on missing `id`, unknown `initial` state, or unknown transition target state; keeps `context` JSON-serializable (`inspectMachines()` never contains DOM nodes or closures); updates bound host `[data-machine]`, `[data-state]`, and `aria-busy` attributes synchronously before invoking `entry`, `effect`, `onTransition`, or `subscribe` listeners; and evaluates `can(event)` safely when called without a payload during `getSnapshot()`.
- `[lab.js:demo-guide]` — Module sibling navigation (`#demo-guide`) is appended to `.intro` only when `.intro` exists, `#demo-guide` is absent, and `id !== 'reading-route'`.
- `[lab.js:run]` — Guards against concurrent re-entrancy via `runner.can('RUN')`, disables the clicked trigger button (`btn.disabled = true`) during `running`, and restores `btn.disabled = Boolean(options.disabledWhen?.())` in `finally`.
- `[lab.js:create]` / `[lab.js:withSession]` / `[lab.js:sessions]` — `create()` throws if `globalThis[name]?.create` is missing or `api.availability(opts) === 'unavailable'`; `withSession()` always invokes `session.destroy?.()`, deletes the session from `sessions`, and dispatches `SESSION_RELEASE` to `sessionPool` in `finally`, while `pagehide` destroys and clears any remaining tracked sessions.
- `[lab.js:cosine]` / `[lab.js:overlap]` — `cosine(a, b)` throws `'Embedding dimensions differ.'` unless both arrays are non-empty and equal length; zero-norm vectors and empty token sets return `0` rather than `NaN`.
- `[decisions.js:routeSchema]` / `[decisions.js:nativeDecision]` / `[decisions.js:airlockMachine]` / `[decisions.js:baseline]` — `nativeDecision` (`issue-router`, `abstention-lab`) enforces `{ route: 'billing' | 'technical' | 'review', reason: string }`, while `comment-airlock` enforces `{ route: 'allow' | 'review', reason: string }` (`additionalProperties: false`), invalidates back to `'editing'` on comment/checkbox edits, and applies deterministic `rules()` (unconditional blank check `!text.trim()`, optional HTTP(S) URL and `> 250`-char checks) that override `finalRoute` to `'review'` (`escalated_review`); `baseline(text, margin = 1)` abstains to `'review'` when both keyword scores are `0` or `|scores.billing - scores.technical| < margin` (`#margin` slider `1..3`).
- `[languages.js:radarMachine]` / `[languages.js:proofreadMachine]` — `language-radar` caps displayed language candidates at 8, clamps bar widths to `[0, 100]%`, and transitions `detected -> stale` on sample or text edits; `proofread-review` validates `typeof r.correctedInput === 'string'`, tracks monotonic `revision` to reject stale mid-flight results, enables `#accept` and `#reject` exclusively in `review_ready`, and auto-transitions `review_ready | accepted | rejected | proofreading -> editing` when `#source` is edited.
- `[lifecycle.js:conciergeMachine]` / `[lifecycle.js:streamMachine]` / `[lifecycle.js:passportMachine]` — `model-concierge` inspects all 6 Built-in AI globals (passing `{ sourceLanguage: 'es', targetLanguage: 'en' }` for `Translator`) and guards single-flight `[data-prepare]` session checks via `conciergeMachine.can('PREPARE_SESSION')`; `stream-garden` coordinates `AbortController` and abort-aware 65 ms rehearsal timers (`waitChunk`) with `aria-busy` on `#app` and `#result`, clearing timers and aborting active streams on cancel or `pagehide`; `iframe-passport` rejects `file:` origins, swaps ports `8080`/`8081` on `'localhost'` and `'127.0.0.1'`, preserves `#probe-result` JSON during `probing` until the verified `ai-policy-probe` `postMessage` arrives (`[lifecycle.js:sameOrigin]`), and transitions to `allowed`, `denied`, or `error`.
- `[performance.js:latencyMachine]` / `[performance.js:preferenceMachine]` / `[performance.js:backpackMachine]` — `latency-lens` gates `EXPORT` on `recorded | exported` (`!latencyMachine.can('EXPORT')` throws in `empty | running`); `preference-kitchen` re-evaluates option compatibility on select changes and blocks `SUMMARIZE` in `invalid_config` when `preference === 'speed'` conflicts with `outputLanguage`, `type`, or `length`; `context-backpack` transitions `measured -> stale` when segment selections or `#question` change and throws when `session.measureContextUsage` is unavailable.
- `[recipes.js:releaseMachine]` / `[recipes.js:prepare]` — `release-kitchen` validates non-empty `/^R\d+:\s*\S/` lines with unique `R\d+` identifiers (`valid <-> invalid_facts`) and audits generated output into `citations_verified` (zero missing/unknown IDs) vs. `citation_drift`.
- `[retrieval.js:rank]` / `[retrieval.js:constellationMachine]` / `[retrieval.js:evidenceMachine]` — `rank` embeds passages with `{ taskType: 'retrieval-document' }` and queries with `{ taskType: 'retrieval-query' }`, rejecting blank queries and mismatched counts; `duplicate-constellation` embeds up to 10 passages with `{ taskType: 'semantic-similarity' }` and invalidates `ready -> stale` (clearing `pairs = []`) on `#add`; `evidence-window` gates `#draft.disabled` via `!evidenceMachine.can('DRAFT')` (`DRAFT` enabled only in `ready_to_draft | verified | citation_warning`), invalidates back to `unranked` on `#query` edits (incrementing `queryRevision` to discard stale in-flight retrievals/drafts), dynamically switches `insufficient_evidence <-> ready_to_draft` on `#threshold` changes, forwards at most 3 passages, and audits `[A]`–`[F]` citations (`verified` vs. `citation_warning`).
- `[webmcp.js:getModelContext]` / `[webmcp.js:add]` / `[webmcp.js:consentMachine]` / `[webmcp.js:observatoryMachine]` — `webmcp=0` and `forceModal=1` override native `modelContext`; `reading-route` rejects non-string or unrecognized `articleId` values, deduplicates `trail`, and queues `#route-toast` updates inside `modalMachine` (`queuedToast`) while `#webmcp-modal` is `open` (inert background); `consent-cart` enforces integer `quantity` in `1..4`, single-flight `awaiting_review` (`!consentMachine.can('STAGE')` -> `REVIEW_PENDING`), and token-scoped `AbortSignal` cleanup; `tool-observatory` requires non-empty `query` in `find_demo`, plain JSON object arguments in `#invoke` (`invalid_json` on parse/shape failure), and hides `debugging: true` tools in `#tools` / `#tool` UI unless `#show-debug` is checked while exposing live `Lab.inspectMachines()` via `inspect_state`.

## Side Effects

- `[lab.js:window.Lab]` / `[lab.js:createMachine]` / `[lab.js:sessions]` — Mutates `document.body.classList`, `document.documentElement` CSS `--accent`, `document.title`, `#title`, `#hook`, `#topic`, `#lesson`, and `#sources`, appends `<nav id="demo-guide">`, updates `[data-machine]`, `[data-state]`, and `aria-busy` attributes on bound host elements, registers a `window` `pagehide` listener, and defines `window.Lab`.
- `[lab.js:create]` / `[lab.js:download]` — Invokes browser Built-in AI `availability()` / `create()` APIs (which can initiate on-device model downloads) and triggers client-side JSON file downloads via temporary `Blob` object URLs (`URL.createObjectURL` revoked after 2000 ms).
- `[decisions.js:routerMachine]` / `[languages.js:proofreadMachine]` / `[performance.js:latencyMachine]` / `[recipes.js:releaseMachine]` / `[retrieval.js:evidenceMachine]` — Hydrates `#app.innerHTML`, binds state-machine-driven event listeners, executes on-device model inference sessions, and exports `native-latency-trials.json` in `latency-lens`.
- `[lifecycle.js:streamMachine]` / `[lifecycle.js:passportMachine]` — Attaches `pagehide` and `message` listeners on `window`, manages abortable 65 ms simulated stream timers, and dynamically sets `<iframe id="probe">` `src` (`iframe-probe.html` on ports `8080`/`8081`) and `allow` attributes.
- `[webmcp.js:register]` / `[webmcp.js:modalMachine]` / `[webmcp.js:copyMachine]` / `[webmcp.js:window.addToRoute]` — Hydrates `#app` and calls `modelContext.registerTool()` across WebMCP demos; specifically on `reading-route`, appends and auto-opens `<dialog id="webmcp-modal" closedby="any">` via `showModal()` when `hasWebMCP()` is false, copies `'chrome://flags'` to clipboard (`navigator.clipboard.writeText` with `document.execCommand('copy')` fallback and `#copy-flag-live` announcements), coordinates toast/copy timers with `pagehide` teardown, and defines `window.addToRoute`.
