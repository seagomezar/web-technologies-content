This guide provides instructions for members of the Early Preview Program (EPP) to test the new smaller and faster expert models for the Summarizer API, and for the Proofreader APIs. These specialized models are designed to enhance performance and accuracy for their respective tasks.
Initial Setup and Configuration
To begin testing, ensure you are using Chrome Version 150+; use Chrome Canary to get nightly updates. You must manually enable the following experimental flags to access the expert models and their associated parameters:


* Summarizer API: Enable chrome://flags/#summarizer-api-performance-preference
   * Follow updates at https://chromestatus.com/feature/6309243756085248
* Proofreader API: Enable chrome://flags/#proofreader-api
   * Follow updates at https://chromestatus.com/feature/5164677291835392
Expert Model for the Summarizer API
Preference Parameter
We have added a preference parameter to the options for Summarizer.create() function. This provides a standard mechanism for developers to indicate whether they prioritize fast execution or comprehensive capabilities. 


The preference parameter addresses a fundamental tradeoff that exists across all client-side machine learning tasks. As such, it may eventually apply to other APIs in the built-in AI ecosystem.
Preference Parameter Options
Preference value
	Description
	"auto"
	(Default) Implementation-defined balance. 


The browser may dynamically adjust internal processing based on environment, system constraints, or context.
	"speed"
	Prioritizes low latency and fast execution. 


This may limit summarization capability, potentially resulting in less nuanced extraction. NOTE: incompatible options will yield unavailable and reject create() calls. 


With this preference, only a subset of the options are currently supported:
* outputLanguage: ”en”
* type: ”tldr” or ”key-points”
* length: “short” or “medium”
* (NOTE) format: ”markdown” output will match that of ”plain-text”


The quality may vary depending on the type of content. We’d love your feedback on which content is working well (e.g. reviews), and what other type of content we ought to prioritize (e.g. chat logs).
	"capability"
	Prioritizes comprehensiveness and coherence. 


This focuses on capturing subtle context and highly refined summaries, which may require longer processing times.
	Example usage
The examples below show how the preference parameter can be used in different scenarios. For details on the Summarizer API itself, refer to full developer documentation.


// Make a summarizer with "speed" preference, with { type: "key-points", format: "markdown", length: "short" } defaults.
const quickKeyPointsSummarizer = await Summarizer.create({preference: "speed", outputLanguage: "en"});
const keyPoints = await quickKeyPointsSummarizer.summarize(myText);


// Make a summarizer with "capability" preference, using context to draft Spanish headlines with { format: "markdown", length: "short" } defaults.
const advancedHeadlineSummarizer = await Summarizer.create({preference: "capability", type: "headline", outputLanguage: "es", sharedContext: myContext});
const headline = await advancedHeadlineSummarizer.summarize(myText);
Expert model for the Proofreader API
The Proofreader API doesn’t expose any preference parameter. It always uses an expert model and is currently limited to English.
Example usage
The example below shows basic usage of the Proofreader API, now powered by an expert model. For additional details, refer to the full developer documentation.


// Create a Proofreader session, and use it to proofread a piece of text.
const proofreader = await Proofreader.create();
const result = await proofreader.proofread(myText);
console.log(result.correctedInput);
console.log(result.corrections);
